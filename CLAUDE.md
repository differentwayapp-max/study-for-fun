# Study for fun – notes for working on this repo

Kids practise for school tests through games; a parent picks or builds practice sets. Hebrew-first PWA (RTL), English UI too.

## Layout
- `public/index.html` – the whole app (one file: UI, games, Firebase bridge). `public/i18n.js` – English translation (dictionary + patterns).
- `public/kid-rest.js` – kid phones' REST fallback (Lockdown mode / no IndexedDB). `public/sw.js` – service worker.
- `functions/index.js` – Cloud Functions (europe-west1): `ask` (Claude via the Anthropic SDK – one STEP per call, never a free prompt), `startBuild`/`endBuild` (3 builds/month per family, paid credits later), `adminUsers`.
  A new practice set is built ON THE SERVER, so the parent may close the phone: `submitBuild` (the form + files; the files are read there – the scan step – and never kept) → `runBuild` (a Cloud Tasks queue: `buildSet` step by step; every answer goes into `builds/{id}/log`, a task hands over after 17 min and a failed task is retried – both replay the log, nothing is asked twice) → the set is written to `families/{f}/sets/s<at>`; the phone only shows `builds/{id}.prog` (`watchBuilds`). `resumeBuild` = "▶ להמשיך" on a stopped build; `endBuild` also cancels / dismisses; `cleanBuilds` (every 6 h) deletes the form and log of builds that are over.
  Question bank (stage 1 – filled and measured, NOT used by builds yet): after a build that ended well, `bankAfterBuild` measures what the bank could have given it (Haiku `match` against `qbankIdx/{gi}_{subject}`; ≤70% of a chapter, 50% with material; → only `meta/qbank_<month>`, never on the build doc the phones read; admins: ☰ → משתמשים) and adds the set's own checked questions to `qbank` (no family/kid/build id; never a catalog question, a reported one, one with a kid's name in it or its topic, or one the server-only `bank` step leaves out – a real person/place or the family's own material). `bankWatch`: a question the parent changes or deletes leaves the bank. These AI calls are the app's cost, never the family's. Test: `e2e_bank.js`.
- `public/build-core.js` – the question pipeline shared by the app and the server (`genChapter`, `poolPick`, `picturePass`, `qaSet`, `codeChecks`, `clean`, `buildSet`…): plain script in the app, `require`d by functions (copied to `functions/build-core.js` by the functions predeploy in firebase.json – never edit that copy). No DOM in it. No monthly AI cap for now, $100 a day for the whole app (80% of it → a server-log alert), at most $8 a month per family; each call reserves its most possible cost first and settles after (`reserve`/`settle`); cost per step on `builds/{id}` and `meta/ai_spend_<month>`. 2 refunds of failed builds per family a month. Admin emails in `functions/.env`.
- `functions/prompts.js` – every AI prompt, built on the server from structured data: the steps (scan, gen, pics, solve, review, fix, report, match, select) with model, effort, max_tokens, input size limits and the JSON schema of the answer; the rules (`BUILD_RULES`, `PIC_RULE`, `COPY_RULE`) in one cached system prompt. In the emulator a test can ask for a fake AI (`window.SFF_FAKE_AI`, `data.fake`).
- `firestore.rules` – who reads/writes what (owner, admin, helper, tutor, kid device, app admins). A tutor reaches only the kids in `members/{uid}.kids` (their sets – asked kid by kid – and progress) and its `tutorView/{inviteCode}` (written by the parent's app: with the invitation, and kept up to date); never the family document, kid links, devices, invitations or other adults. Test: `e2e_tutor.js` + section 9–10 of `e2e_security.js`.
- `tools/sets/*.py` + `tools/build_set.py` – hand-built catalog practice sets → `public/share/`. `tools/pic_rules.py` – the picture never gives the answer away (a naming question shows the thing to name; any other question shows all the options or its data, never the right option alone); no emoji newer than 2019. `SFF_DRY=1 python3 -I tools/build_set.py <file>` checks a set without writing.
- Teachers' groups (plan + decisions: `docs/teacher-area-plan.md`): `families/{random 20-char id}` with `kind:'class'`, `ownerUid` (made only by `createClass`, ≤ 10 a teacher, removed by `deleteClass`). AI building in a group counts on the TEACHER, not the group (`scopeOf(famId)` in functions: a family → `families/{f}/usage`, a group → `teachers/{ownerUid}/usage/{month}`; `TEACHER_FREE_BUILDS = 5`, `TEACHER_CAP_USD = 12`, no paid builds; the first build ever is free to try, from the second at least `MIN_STUDENTS = 3` approved students in their groups → `need_students`; a teacher who is also a parent keeps the family's own quota). A group's build is one shared set (no kid's id or name, `grp: 1`) given out as an assignment. Parents' consent (stage 2): the group's link `/?join=<group>.<code>` (`joinLink`: 30 days, close / new) → a parent with no account (anonymous) reads the letter, signs with a finger → `requestJoin` (≤ 5 an hour a phone, ≤ 60 waiting) → the parent's status link `/?req=<group>.<id>.<key>` (`joinStatus`; only the key's hash kept) → the teacher `approveJoin` (new student or a second parent) / `rejectJoin` (the teacher never adds students, no paper forms); `revokeConsent` (parent or teacher) deletes the student's progress, phones and link. Only the server writes `consents/{kid}`, `joinReqs`, `joinLink`, `kidpub/{kid}` and a group's `fam/*`; a kid phone joins a group only with a consent and reads only its own student (`kidpub`), progress and sets. The letter: `tools/docs/consent-{he,en}.md` → `python3 -I tools/build_docs.py` → `public/consent.html` (`?t=&g=`) + `public/consent.json`; its version = `CONSENT_VERSION` in index.html (kept with every request and consent). QR: `public/qrcode.js` (qrcode-generator 1.4.4, MIT). Tests: `e2e_teacher.js`, `e2e_consent.js`, sections 11–12 of `e2e_security.js`.
- The teacher's screens (stage 3, `docs/teacher-area-plan.md` §11): worked out on the teacher's phone from the students' progress it already reads (live, nothing sent anywhere): `classReport` (per topic: a student's mastery = the right answers in their last 10 questions of it, `kidMastery`; 80%+ / 60–79% / under 60% / not practised; weakest topic first; trend vs the period before), `hardQuestions` (the wrong answer chosen most), `classAttention` (stuck = the last two games on the same chapter under 50%; didn't practise this week; doing well) → the "מעקב" tab of a group (`renderTeacherStats`: topic list, a topic's page, students × topics map, print without names – `trPrint`), the teacher's home (`teacherAttention`) and a student's card (`kidCardStats` + a private note: `notes/{kid}`, only the group's teacher – rules). Removing a student deletes their progress, phones, notes and practice sets (`dropStudent`). Test: `e2e_class_report.js`.
- Assignments (stage 4, `docs/teacher-area-plan.md` §12): one shared set per assignment – `sets/{id}` with `to: 'all' | [kidId…]`, `toMap: {kidId: true}` (the same students – a student's phone asks `set.to == 'all'` and `set.toMap.<its id> == true`, the only list queries the rules can prove), `due` (= `examDate`, so the chapters spread over the days), `ass: {by, at, closed?, mist?, review?, start?}`; never a kid's id or name (rules: `sharedOk`). The teacher: "＋ משימה חדשה" → `asgOpen` (what: the catalog / a set already in the group / a build → to whom: all / a choice with "need strengthening" from the report / one → by when, + core facts again in two weeks), the home's progress (`teacherAssignments`, `tAsg`: finished / in the middle / not started, close, delete), "תרגול מהטעויות" from the student's card (`tMistakes`, no AI). The student: the bar at the top of the home (`kidAsgBar`); past its date it stays, marked. Old per-kid group sets (with kidId) keep working. Test: `e2e_assign.js`; the quota: `e2e_quota.js`; a build from a group: `e2e_build.js` §6.
- The teachers' intro (`t1`–`t5` for an invited tutor, `s1`–`s6` for a class teacher; a private teacher gets the `s` screens in a tutor's words and purple – `IN.mode`): `openTeacherIntro(mode, only)`; seen → `users/{uid}.introTutor` / `.introTeacher` (the parent's `intro` untouched); ☰ → איך זה עובד = `openHowItWorks()` (the last screen of the series). Screens / parts not built yet wait behind `TSTAGE` (`assign` – s3 homework, `classAI` – "from a photo", `parentReport` – the report on s5): turn on with their stage. Test: `e2e_intro_teacher.js`.
- תרגול ממוקד – focused practice (one name everywhere): `focusOf(set)` – what is left to strengthen (words / questions with mistakes, topics under 80%), from the history only (never the progress screen's state) – used by the progress screen, the kid's card at home and "חדש!". One button: mistakes → `makeFocus` (a `reinf` set right away, no AI, no build used; one station per source chapter – a word goes to the chapter where it was missed – so questions never checked together never meet in memory / match); only weak topics → `focusTopics` (an AI build, with the builds left: it gets the source's own questions of those topics, `reinfMat` → `I.mat`, the gen prompt asks only about them, no catalog questions, `matOnly` drops a word answer not in it). Memory / match never put two look-alike cards (the same picture / text, or the same value in another form) with different answers in one game (`noClash`). Test: `local_focus_fix.js`, `e2e_build.js` §7. ## Run the tests
Serve the app, then run a test inside the emulators:
```
python3 tools/serve.py 8765 &      # like the hosting: /teach (and any address without a file) gets index.html
firebase emulators:exec --only firestore,auth --project study-for-fun-7b03c "node tools/tests/e2e_family.js"
```
Tests that call Cloud Functions need `--only functions,firestore,auth` (e2e_quota, e2e_users, e2e_security, e2e_bank, e2e_build – a whole server build with the fake AI: retried step, "▶ continue", the phone closed mid-build; the Cloud Tasks emulator starts with functions). Run each such test in its own emulator session (accounts add up).
Kid links are per kid (`kidTokens.<kid>` in the family doc, made by `__sffFamily.kidLink(kid)`); a kid device writes only its own kid's progress. Local-only tests: `node tools/tests/local_*.js`.
Full screen walk (Hebrew + English, phone width): `OUT=/tmp/qa node tools/tests/qa_screens.js` inside the emulators (with functions).
Test hooks: `window.SFF_REST_EMU` (emulator addresses) and `window.SFF_TEST_GOOGLE` (fake Google account) – set them with `addInitScript`.

## Deploy
`tools/deploy.sh "message"` – bumps the version everywhere (sff-vN), commits, deploys hosting, pushes to GitHub.
Functions: `firebase deploy --only functions` (its predeploy copies public/build-core.js). Rules: `firebase deploy --only firestore:rules`. A change to `public/build-core.js` needs BOTH a hosting deploy and a functions deploy.
Catalog set: `python3 -I tools/build_set.py tools/sets/<file>.py` (one emoji per picture item – use `COUNT(("🍎",3))` for counting pictures), then `IDS=<id> node tools/tests/local_scenes.js` with the app served (renders every picture: 0 bad scenes), then deploy (existing copies update automatically, progress kept).

**Practice sets – the skills are mandatory:** before building, extending or rewriting any practice set (a catalog set in `tools/sets/` or a set for a family), invoke the `build-practice-set` skill and follow it; when the set is done, invoke `review-practice-set` and review it before reporting or asking to deploy. The same rules run inside the app's AI building (`BUILD_RULES`, `PIC_RULE`, `COPY_RULE` in the system prompt of `functions/prompts.js`, the reviewer step `review` and the code checks in `qaSet`/`codeChecks` in index.html) – keep them in step with the skills.
Skills: `.claude/skills/build-practice-set` (all the rules for writing a set) and `.claude/skills/review-practice-set` (how to review and report). `node tools/match_list.js <id>` lists each chapter's match-game questions and answer cards. `tools/core_facts.json` marks each set's core facts (they come back as review questions in later stations, `reviewQs`).

User guide + terms: edit `tools/docs/{guide,terms}-{he,en}.md`, then `python3 -I tools/build_docs.py` → `public/guide.html`, `public/terms.html`.
When the terms change, update the date in terms-*.md AND `TERMS_VERSION` in index.html – every adult then approves once again.
The privacy policy's date goes in `PRIVACY_VERSION` (recorded with each approval; a change alone asks nothing again).
Approval: ONCE per adult, after the sign-in (no tick box on the sign-in screen); recorded by the server only (`acceptTerms`):
`users/{uid}.terms = {v, privacy, at}` + one line per approval in `users/{uid}/consentLog` (versions, server time, app, sign-in
provider) – the phone cannot write either (rules). Offline: `sff_terms_pending`, recorded on the next open. Test: `e2e_terms.js`.
